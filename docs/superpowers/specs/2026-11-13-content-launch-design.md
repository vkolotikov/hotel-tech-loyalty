# Content launch completion

The owner accepted the written pre-launch audit and explicitly requested **all improvements and fixes, then deployment** on 13 November 2026. This is the implementation design for that authorized work. The audit is `docs/audits/2026-11-13-content-prelaunch.md`; its F01–F17 and additional recommendations are the acceptance checklist. Routine architecture choices below are implementation rulings, not new customer requirements.

## Intent and approach

Make HexaTech Content reliable for paid customers and practical for a team producing and manually publishing content. Preserve the existing Laravel/React workspace, its approved navy/light Atelier tokens, serif display, sans body and restrained violet AI actions. Extend the current services; do not build a second planner or change the public booking widget.

Considered: isolated symptom patches; replacing the planner; extending the existing shared services and workspace. Choose the third: the audit proves concrete boundary errors, and the existing tests/features are useful. Symptom patches would retain incomplete write/guard rules; replacement would risk the working product and change its familiar design.

## Reliability contracts

- F01: only actual `User::isPlatformAdmin()` bypasses subscription checks. Customer owners, managers and staff require an active subscription/trial. Recovery account routes remain accessible.
- F14 and invite race: team seats count active staff. Every activation/invitation checks the limit **inside** the organisation lock. Reinviting an existing active account consumes no new seat. Inactive staff can be edited without activation; reactivation cannot exceed quota.
- F02: keep the existing `updated_at` API as the revision token, with six fractional digits and a strictly increasing logical timestamp on meaningful post saves. Add a PostgreSQL precision migration and model date format; a write under the post lock advances at least one microsecond even with a frozen/backward clock. Compare full instants, not seconds. No-op reads/group bookkeeping and quality checks retain their deliberate version semantics. Frontend comparisons preserve microseconds. This avoids replacing every existing API client and keeps old tabs' raw timestamp tokens meaningful.
- F03/F10: provider work is outside database locks; commit locks and rereads the post, compares the captured revision, then writes normalized words/brief/status/history atomically. A newer edit, publication, changed platform or deletion is preserved and yields a safe conflict. Normalize AI varchar fields against the schema. Every relevant text/brief/image writer uses this boundary.
- F08: one publication transition stamps `published_at` when entering Published, whether via Create, Save or Mark published. Existing timestamps are retained on repeated marking; leaving Published clears publication metadata. Repair legacy Published/null rows conservatively from their saved date/time (or updated_at when no day), documented and tested.
- F11: API reads and failures expose only local image error codes/safe wording, including historical stored exceptions. Provider details remain in server diagnostics.
- Approvals cover the complete post: staff changes to images, assigned media or briefs invalidate Approved/Ready and record the review event, as word edits do.
- F09/F12: every paid AI attempt checks a fresh organisation allowance in shared state, including worker execution, weekly chunks, repairs/retries and image fallback. Serialize Content allowance decisions and recording across its workers/brands. Preserve partial results with a budget reason. Recheck subscription/workspace/staff rights before queued work. Generation checks venue today at execution and immediately before each insert; cancelled/stale runs cannot write.

## Asynchronous AI

Add brand/tenant-scoped work records with action, requester, input, captured post revision, state, result, safe error, start/end/cancel times and an idempotent request key. New `POST content/work`, `GET content/work/{id}`, `GET content/work?post_id=…`, `DELETE content/work/{id}` support Write, Rewrite, Quality, Brief, Image and Fill. Actions run on the existing `ai` queue. The new UI polls and can leave/reopen while work runs; cancellation prevents any subsequent result commit. Existing action routes stay compatible and use bounded requests plus the same safe commit rules. Each work DTO includes can_cancel for its current viewer; requester identity and raw inputs remain private. Calendar generation gains cancellation using its existing run ownership. Do not blindly retry paid ambiguous requests.

## Planning settings and locations

F13 is resolved without silently converting customers' stored wall-clock dates. Content's clock banner uses the same saved planning zone as Content bootstrap/reminders. When unset, it explicitly says UTC and asks a manager to choose a zone. Provide manager-only planning timezone setup through Content settings, validating IANA zones and using the existing venue setting writer. Account-wide consequences are explained before save. Other booking/member clock rules are unchanged.

Content-only customers can manage the purchased locations inside Brand: own current-brand Property rows, minimal name/address/city/country/timezone/contact fields, no PMS credentials or booking configuration. Managers create/update/activate locations within the existing organisation-wide property quota under lock; staff read. Existing locations remain and no destructive delete is needed. Active location descriptions join the Content AI context. Three-location Pro copy now corresponds to an accessible workflow. Changing a location does not silently change the saved planning timezone.

## Draft and navigation behavior

- F04/F05: every asynchronous completion belongs to its originating brand and editor opening. Late responses update only that cache and never replace another dirty draft. Create and Save compare later edits against the **submitted snapshot**, preserving intentional undo and typing. The Create success changes identity in place rather than losing the draft.
- F06: all Brand/summary/bio/list forms register dirty state. Workspace links, Find, brand switch, Full admin, sign-out and unload either retain the draft or ask before discarding. Browser Back restores the appropriate unsaved draft; no draft crosses account/brand. New section navigation respects the same guard.
- F07: placeholder data is reusable only within the same brand.
- F15: the phone/full overlay editor traps visible focus and makes covered content inert; the desktop dock remains nonmodal. Focus is restored on close.
- F16: the document language follows the active UI locale. Post preview uses the post's own language when different.
- Failed reads offer a real Retry which repeats the failed request.

## Schedule export format decisions

CSV is intended for human spreadsheet viewing. Correctly quote multiline/UTF8 cells and prefix risky formula starts (including leading control/whitespace and full-width forms) with a tab inside the quoted field, following the current [OWASP guidance](https://owasp.org/www-community/attacks/CSV_Injection). Explain that programmatic import may retain this tab; do not promise universal safety through arbitrary spreadsheet save/re-import operations.

Emit a UTF8 BOM for ordinary Excel opening of Cyrillic/accented text, following [Microsoft's guidance](https://support.microsoft.com/en-us/excel/opening-csv-utf-8-files-correctly-in-excel). Programmatic readers may strip that first marker. For timed ICS conversion, follow RFC5545 section3.3.5: repeated wall time means the first occurrence; nonexistent wall time uses the pre-gap UTC offset. This interprets the export without changing stored digits.

CSV includes filtered undated posts with empty date/time. ICS exports scheduled posts only, clearly stated beside the controls and in Guide; an untimed dated post is an all-day date-only event. Count the actual exportable selection against5000. Empty returns422 export_empty; more than5000 returns422 export_too_many with refine-filter guidance. Never silently truncate. Bound memory while selecting/streaming; do not materialize thousands of full post graphs. Timed ICS derives instants from the saved planning zone for export only, without changing stored wall-clock digits; use UTC or complete RFC5545 timezone definitions, stable UIDs, CRLF, escaped TEXT and UTF8 octet-aware folding.

## Collaboration inbox ordering

Inbox ordering preserves the full fractional wall-clock instant for comments, approval events, recipient notifications and seen markers. A comment or approval created after the list's read_at remains unread even within the same second, including when the client marks the original list seen after the new event arrives. Keep the existing read_at/seen-at API compatible, preserve historical content and the separate logical post_updated_at revision, and retain comments' no-post-version semantics. A PostgreSQL reproduction on13November confirmed that truncated stored comment/seen timestamps currently lose such a notification; Task7 adds a regression and repairs the relevant persisted precision on PostgreSQL and SQLite.

Review emails follow the existing semantic approval events and inbox recipient policy, including an explicit Create/Save transition into review and changes after approval. Ordinary saves/uploads/previews without a review or mention event do not send mail. This clarifies the plan's no-save-mail test wording without suppressing an explicitly requested approval step; the personal consent still defaults off and delivery authorization is checked again.
